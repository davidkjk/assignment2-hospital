# 시연용 클릭 목업(데모 프론트엔드) 설계

> 2026-08-21. 목적은 **설계 검증이 아니라 시연**이다 — 프로젝트가 계획한 화면을 눈으로 보고, 버튼을 누르면 다음 화면으로 넘어가는 것을 보여준다. 실제 구현체(환자 앱 Flutter, 직원 웹 React)와는 **별개의 "보여주기용 껍데기"**다.

## 1. 목적과 범위

- **목적**: 계획된 화면을 브라우저에서 클릭 가능한 형태로 시연. 실제 DB·로직에 연결하지 않는다.
- **1차 범위**: **환자 앱**만 완결. 검증되면 직원 웹 → 챗봇으로 확장(별도 세션).
- **전달**: 로컬 `npm run dev`로 돌리고, 최종적으로 **공유 URL(Vercel)**까지 배포해 링크로 누구나 열람.

## 2. 원칙 (무엇을 정본으로 삼나)

- **정본 = `screen-behaviors.md`(무엇/흐름) + 결정 문서(왜) + 스펙/플랜.** 목업 132장은 정본이 아니라 **조감도(스케치)**이며 일부는 낡음(취소선). 어긋나면 **규칙이 이긴다.**
- **비용을 아끼는 읽기 순서**: 화면마다 ① `spec-index/SPECINDEX-patient-app.md`에서 해당 묶음의 규칙 위치를 찾고 → ② `screen-behaviors.md`의 **그 줄 슬라이스만** 펼치고(1MB 전체 통독 금지) → ③ 해당 목업 HTML을 **레이아웃 참고**로만 본다.
- **해피패스만**: 데모는 눈에 보이는 정상 흐름만 구현한다. 오프라인·낙관적 잠금·409 충돌·예외 마스킹 등 **보이지 않는 엣지 규칙은 제외**(범위 밖).
- **테마**: 프레임 목업 단계라 **shadcn 기본 테마(회색 기본값)**를 쓴다. 확정 디자인(딥틸 `#0B6E70`·Pretendard·Solid 아이콘)은 앱이 다 붙은 뒤 마지막에 입힌다.

## 3. 기술 스택

- **Vite + React + TypeScript + TailwindCSS + shadcn/ui(기본 테마)**
- 라우팅: `react-router`(클라이언트 라우팅, 실제 인증 없음 — 버튼이 경로를 바꾼다)
- 상태/데이터: 실제 백엔드 없음. **가짜 데이터 모듈 + 화면 안 임시 상태**(예: 예약하면 목록에 1건 추가되는 정도의 가짜 반응)
- 배포: **Vercel**(정적 SPA 빌드)

## 4. 구조

- 새 최상위 디렉토리 **`demo/`** 에 단일 Vite 앱. (실제 `backend/`·`supabase/`와 분리)
- **폰 프레임 셸**: 환자 앱은 휴대폰 앱이므로 화면 가운데 휴대폰 크기 틀(예: 390×844) 안에 렌더. 틀 밖은 데모 배경.
- **한 단위 = 한 화면 묶음**. 각 화면은 자기 폴더 안에서 독립적으로 이해·수정 가능하게(공용 UI는 `components/`, 가짜 데이터는 `mock/`).

## 6. 순서 (슬라이스로 나눠 진행)

1. **세션 1 (이번)**: 프로젝트 뼈대(Vite+React+Tailwind+shadcn+폰 프레임+라우팅+가짜데이터 틀) + **첫 수직 슬라이스** = 로그인 → 홈 → 예약 8단계 → 완료(약 6~8화면). 여기까지면 처음부터 끝까지 클릭되는 데모가 돌아간다. **패턴 확정 지점.**
2. **세션 2+**: 나머지 묶음(4 상세·변경/취소, 5 문진, 6 가족, 7 이력·설정, 2의 알림함) 순차 추가. 패턴이 검증됐으면 이 지점에서 **병렬 워커**로 나눌 수 있다(규칙상 창 수·범위 사전 보고·승인 후 실행).
3. **마무리**: 확정 테마(딥틸·Pretendard) 입히기 → Vercel 배포 → 공유 URL.
4. **확장(별도)**: 직원 웹 → 챗봇.

## 7. 범위 밖 (YAGNI)

- 실제 Supabase 연결·실제 인증/OTP·실제 예약 로직
- 오프라인 캐시, 낙관적 잠금/409, 예외 마스킹 등 비가시 엣지 규칙
- 초기 단계의 확정 테마(마지막에만 적용)
- 직원 웹·챗봇(1차 범위 밖, 이후 확장)

## 8. 정본 대조 절차 (화면 하나 만들 때마다)

1. `SPECINDEX-patient-app.md`에서 묶음 규칙 위치 확인 →
2. `screen-behaviors.md` 해당 슬라이스만 읽기 →
3. 목업 HTML로 레이아웃 참고 →
4. React+shadcn(기본테마)로 해피패스 구현 + 가짜 데이터 →
5. 버튼 → 다음 경로 연결. 규칙과 목업이 어긋나면 규칙을 따르고, 그 사실을 기록.
