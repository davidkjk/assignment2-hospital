# 상담봇 정본 (2026-07-27 스펙을 덮어쓰는 현재 결정 모음)

> 이 파일은 상담봇 목업의 근거다. 옛 스펙과 충돌하면 이 파일이 이긴다.
>
> 표기: `결정로그 Lx–y`는 `docs/superpowers/specs/2026-07-31-ui-design-decisions.md`의 줄번호, 영문 대문자 ID는 `docs/design/screen-behaviors.md`의 규칙 ID다. `옛 스펙 Lx–y`는 비교 대상으로만 적으며, 정본 근거는 각 항목의 결정로그 줄번호 또는 규칙 ID다.

## §0 용어·전역 규칙

- 환자에게 보이는 이름은 모두 **`AI 상담봇`**이다. 내부 파일명·코드의 `chatbot`은 바꾸지 않아도 되지만 화면 글자에 `챗봇`을 쓰지 않는다. 근거: 결정로그 L216–219, `BOOK-BOT-02`.
- 앱의 하단 탭 이름은 요구사항 원문 그대로 **`AI 상담`**이며 FAB가 아니다. 직원 인계 사실은 메뉴 이름을 바꾸지 않고 상담방 안의 상태로 알린다. 근거: 결정로그 L69–77.
- 화면과 카드가 모르는 상태·시간·사유를 만들어 말하지 않는다. 특히 예상시간은 실제 운영시간 판정에 따르고, 취소가 확정되지 않은 상태를 `취소 요청 접수` 또는 취소 완료처럼 표현하지 않는다. 근거: `SCHED-HOURS-03`, `CANCEL-LATE-12~13`.
- 앱·웹·상담봇이 함께 쓰는 판단은 서버 한 곳의 값을 소비한다. 병원 운영시간·휴무 판정은 단일 함수, 문진 진행률은 단일 서버 계산, 예약 충돌은 동일 예약 API 결과를 쓴다. 근거: `SCHED-EXC-12`, `QNR-PROG-04·09`, `BOOK-RACE-01~07`.
- 빠른 답변 버튼은 별도 제어 신호가 아니라 그 문장 그대로 **환자가 보낸 말풍선**이 된다. 자유 입력창은 항상 열어 둔다. 근거: 결정로그 L816–818, L827–833.
- `예약 중 상담`과 독립 `AI 상담`은 같은 엔진의 다른 모드다. 예약 중 상담 모드는 **정보성 안내와 진료과 추천만** 하며 예약제안·취소·문진 카드 등 모든 행동형 도구를 금지한다. 유일한 행동 출구는 `○○과로 계속하기`이고, 긴급(119/응급실) 안전 안내는 모드와 무관하게 항상 작동한다. 근거: 결정 E4; `BOOK-BOT-01~08`.
- 제한 자료와 일반 자료가 함께 걸리면 일반 자료는 평소대로 답한다. 제한 주제는 병원이 작성한 문구를 **글자 그대로, 봇 생성문 밖의 별도 블록**으로 보여주며 봇이 살을 붙이지 않는다. 질문 전체가 제한 주제면 제한 문구와 `[직원 연결]`만 보여준다. 근거: 결정 A3; `KBADM-EDITOR-04`.
