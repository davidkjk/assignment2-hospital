# 상담봇 채팅 카드 사전

> ⚠️ MERGED → docs/ (2026-08-13). 이 파일은 아카이브. 이후 변경은 docs/ 정본에 직접.

> 범위: 환자 앱·웹 상담창이 같은 판단을 재현해야 하는 채팅 카드 8종의 내용·상태·동작 계약.
> 이 문서는 목업 전 게이트이며 카드의 픽셀 크기, 여백, 열 수, 배치와 같은 시각 수치를 확정하지 않는다. 상담봇 전용 레이아웃은 아직 미결이다. [근거: `chatbot-source-of-truth.md` L38–40, L84–90; `chatbot-screen-inventory.md` L120–126]
> 우선순위: `chatbot-source-of-truth.md`가 정본이며 다른 문서와 충돌하면 정본을 따른다. [근거: `chatbot-source-of-truth.md` L1–5]

## 공통 원칙

1. 환자 노출 이름은 `AI 상담봇`으로 통일한다. 앱 하단 탭 이름만 `AI 상담`이다. [근거: 정본 L7–10; `BOOK-BOT-02` (`screen-behaviors.md` L3431–3433)]
2. 카드는 앱 전체화면의 레이아웃을 복사하는 컴포넌트가 아니라, 앱과 같은 **판단·상태·문구·실행 결과**를 대화 피드에서 재현하는 컴포넌트다. 목업 92의 일반 봇 말풍선보다 넓은 세로형과 상단 윗꼬리표를 유지하고, 더 분명한 테두리·배경 톤으로 말풍선과 구분한다. [근거: 정본 L38–40, L84–90; 결정회의 안건 1 L52–63; 결정로그 R2-1]
3. 앱·웹·상담봇이 공유하는 판단은 같은 서버 값을 소비한다. 시간 가용성, 예약 충돌, 문진 진행률을 카드가 따로 계산하지 않는다. [근거: 정본 L11–12; `BOOK-RACE-01~07`, `QNR-PROG-04·09`]
4. 모르는 상태·시간·사유를 만들어 쓰지 않는다. 특히 취소 확정 전에는 `취소 요청 접수`, `취소 완료`, 자동 취소를 암시하는 표현을 금지한다. [근거: 정본 L11; `CANCEL-LATE-12~13` (`screen-behaviors.md` L3779–3781)]
5. 되돌릴 수 없는 실행은 확인 카드 안의 명시적인 확정 버튼에서만 일어난다. 선택 단계와 제안 단계는 서버 실행이나 슬롯 선점이 아니다. [근거: `BOOK-HOLD-01~03` (`screen-behaviors.md` L3382–3389); `CANCEL-PRE-01~06` (L3739–3748)]
6. 처리 중에는 원래 버튼의 뜻이 보이게 유지하고 중복 입력을 막는다. 실패는 원인이 된 버튼 가까이에 남기며, 재시도는 별도 행동을 만들지 않고 원래 버튼을 다시 사용한다. [근거: `BOOK-CONF-05~09` (`screen-behaviors.md` L3520–3524); `APPT-BTN-11~12` (L3697–3698)]
7. 빠른 답변을 누르면 버튼 값이 제어 신호가 아니라 그 문장 그대로 환자가 보낸 말풍선으로 저장된다. 자유 입력창은 항상 사용할 수 있어야 한다. [근거: 정본 L13; 결정로그 L816–818, L827–833]
8. `예약 중 상담` 모드는 진료과만 정해 예약 마법사로 돌려준다. 이 모드에서는 시간선택·예약확인·예약완료 카드를 보내지 않는다. [근거: 정본 L14, L21–22, L50; `BOOK-BOT-04~08` (`screen-behaviors.md` L3434–3438)]
9. 앱과 웹은 같은 카드 규칙과 API 결과를 쓰되, 각 그릇에 맞춘 배치는 목업에서 별도로 정한다. 웹에서 마감 후 취소·변경 진입을 앱과 똑같이 복제할 근거는 아직 없다. [근거: `chatbot-screen-inventory.md` L43–58, L127]
10. 카드와 일반 봇 말풍선은 넓은 세로형·상단 윗꼬리표·강화된 테두리와 배경 톤으로 구분한다. 다만 일반 병원 안내와 의료 관련 안내를 색 이외 어떤 표식으로 구분할지는 **확인 필요**이며, 아이콘·좌측 바를 임의로 추가하지 않는다. [근거: 정본 L38–40, L88; `CHAT-ROOM-VISUAL-01`; 결정회의 안건 1 L52–63; 결정로그 R2-1]
11. 일반 자료에는 평소대로 답한다. 제한 주제는 병원이 쓴 문구를 **글자 그대로**, 봇 생성 텍스트 밖의 별도 블록으로 보여주고 살을 붙이지 않는다. 질문 전체가 제한 주제면 제한 문구와 `[직원 연결]`만 표시하며, 제한 주제 때문에 무관한 일반 안내까지 막지는 않는다. [근거: `KBADM-EDITOR-04`; 결정 A3]

## 상태 표기 규약

| 표기 | 뜻 | 카드 동작 | 근거 |
|---|---|---|---|
| 정상 | 서버에서 유효한 현재 값을 받아 행동할 수 있음 | 현재 데이터와 실행 가능한 버튼만 표시 | 정본 L11–12 |
| 빈 | 조회는 성공했으나 가능한 대상이 0개임 | `0개`의 이유와 다음 경로를 함께 제공; 실패처럼 재시도시키지 않음 | `BOOK-TIME-06~07` (L3493–3495) |
| 처리 중 | 사용자의 실행 요청을 보냈고 결과를 기다림 | 버튼 문구의 의미를 유지하고 중복 실행 잠금 | `BOOK-CONF-05~08` (L3520–3523) |
| 실패 | 요청 또는 조회가 실패함 | 성공처럼 바꾸지 않으며 원인 가까이에 오류와 유효한 재시도 경로 제공 | `BOOK-CONF-09` (L3524); 인벤토리 L24–31 |
| 충돌/409 | 선택 뒤 서버의 최신 상태와 달라짐 | 같은 API 결과를 받아 최신 데이터로 다시 그리고, 바뀐 사실을 말함 | `BOOK-RACE-01~07` (L3546–3552); `APPT-RACE-01~08` (L3704–3711) |
| 읽기 전용 | 기록은 보존하지만 현재 상태에서 수정할 수 없음 | 내용을 숨기지 않고 수정 행동만 제거하며 이유를 표시 | `CARD-QNR-03~05` (L3232–3234); `APPT-QNR-05~06` (L3678–3679) |
| 확인 필요 | 정본이 저장·상태·화면 계약을 아직 확정하지 않음 | 목업과 구현에서 추측하지 않고 미결 표기를 유지 | 정본 L84–98 |

상태 수는 아래 각 절의 `상태 변형` 표에 번호를 붙인 행만 센다. 버튼 수는 동시에 렌더링되는 인스턴스 수가 아니라 `버튼 동작 종류`를 센다. 조건부·미결 버튼은 요약에서 별도로 밝힌다. [근거: 인벤토리 L4–6; 이 문서의 계수 정의]

## 1. 시간선택 카드 `CCARD-TIME`

### 목적과 재현 규칙

- 실제 예약 가능한 날짜·시간만 버튼으로 제안하고, 선택 뒤 슬롯 소진 시 다른 시간을 고를 수 있게 한다. [근거: 인벤토리 L24, L51; 정본 L45, L48]
- 재현 규칙: `BOOK-TODAY-01~13`, `BOOK-TIME-01~08`, `BOOK-HOLD-01~06`, `BOOK-RACE-01~09`. [근거: 정본 L45, L48; `screen-behaviors.md` L3466–3495, L3382–3391, L3540–3554]

### 상태 변형 — 5종

| # | 상태 | 카드 계약 | 근거 |
|---:|---|---|---|
| 1 | 정상 | 당일이면 지난 시각, 의사별 마감 이후, 지금부터 30분 이내를 제외하고 실제 가능한 후보만 보여준다. | `BOOK-TODAY-01~13` (L3470–3482); `BOOK-TIME-02` (L3489) |
| 2 | 빈 | 가능한 시간이 0개이면 빈 덩어리를 남기지 않고 이유와 `[다른 날짜 고르기]`를 제공한다. 30분 규칙으로 0개면 그 이유를 말한다. | `BOOK-TIME-06~07` (L3493–3495); `BOOK-TODAY-13` (L3482) |
| 3 | 조회 중 | 후보 조회가 끝나기 전에는 선택 가능한 시간처럼 보이지 않는다. 구체적인 스켈레톤 모양은 목업에서 정한다. | 인벤토리 L24, L51; 정본 L40 |
| 4 | 조회 실패 | 성공/0개로 가장하지 않고 조회 실패와 재시도 경로를 같은 카드 맥락에 둔다. 구체적인 오류 배치는 목업에서 정한다. | 인벤토리 L24, L51; `BOOK-NAV-10` (L3380) |
| 5 | 슬롯 충돌 | 소진된 시각을 말하고 후보를 다시 조회한다. 소진 슬롯은 회색으로 남기지 않고 목록에서 빼며, 팝업을 띄우지 않는다. | `BOOK-RACE-01~09` (L3546–3554) |

### 버튼과 동작 — 3종(동적 인스턴스)

| 버튼 동작 종류 | 동작 | 실행 성격 | 근거 |
|---|---|---|---|
| 날짜 후보 `[날짜]` | 해당 날짜의 서버 가용 시간을 조회해 같은 예약 흐름에서 시간 후보를 연다. 날짜 후보를 한 카드에 둘지 앞선 대화 턴으로 나눌지는 목업 확인 필요다. | 선택, 예약 실행 아님 | 인벤토리 L24; `BOOK-TODAY-01~13` (L3470–3482); 정본 L40 |
| 시간 후보 `[시각]` | 선택값을 다음 예약확인 단계로 전달한다. 선택만으로 슬롯을 잡지 않는다. | 선택, 슬롯 선점 아님 | `BOOK-HOLD-01~03` (L3386–3388) |
| `[다른 날짜 고르기]` | 날짜 선택 맥락으로 돌아가 다른 날짜를 고르게 한다. | 이동 | `BOOK-TIME-07` (L3494) |

### 채팅 그릇 이슈와 정합성

- 가능한 시각을 봇의 긴 대화문으로 나열하지 않고 선택 가능한 버튼 데이터로 제공한다. 오전/오후 묶음과 열 수를 채팅 카드에서 그대로 복제할지는 픽셀 목업에서 정한다. [근거: 인벤토리 L24; `BOOK-TIME-01~05` (L3488–3492); 정본 L40]
- 카드가 자체 캐시로 “가능”을 확정하면 안 된다. 최종 신청 직전까지 선택은 선점이 아니며 충돌은 예약 API 결과로 처리한다. [근거: 정본 L12, L48; `BOOK-HOLD-01~06`, `BOOK-RACE-01~09`]

## 2. 예약확인 카드 `CCARD-BOOKCONF`

### 목적과 재현 규칙

- 대상·진료과·의사·일시·방문이유·장소를 한 번에 최종 확인하고 명시적 신청 버튼으로 예약을 실행한다. [근거: 인벤토리 L25, L52; `BOOK-CONF-01~04e` (L3512–3519)]
- 재현 규칙: `BOOK-WHO-01~03`, `BOOK-WHY-01~06`, `BOOK-CONF-01~09`, `BOOK-HOLD-01~06`, `BOOK-RACE-01~09`, `BOOK-BOT-07`. [근거: 정본 L44, L46–50]

### 상태 변형 — 4종

| # | 상태 | 카드 계약 | 근거 |
|---:|---|---|---|
| 1 | 정상 | 대상(가족이면 관계 포함), 진료과, 의사, 일시, 선택 입력인 방문이유, 장소를 함께 보여주고 버튼 문구는 설정과 무관하게 `예약 신청하기`로 통일한다. | `BOOK-WHO-01~03` (L3409–3411); `BOOK-WHY-03·06` (L3503, L3506); `BOOK-CONF-02·04b~04e` (L3513, L3516–3519) |
| 2 | 신청 처리 중 | 원래 버튼 자리에서 `예약 신청 중…` 의미를 유지하고 중복 신청을 막는다. 오래 걸려도 앱이 임의로 끊거나 재신청시키지 않는다. | `BOOK-CONF-05~08` (L3520–3523) |
| 3 | 신청 실패 | 버튼 바로 가까이에 오류를 유지하고 원래 `예약 신청하기` 버튼으로 다시 시도한다. 성공 카드로 전환하지 않는다. | `BOOK-CONF-09` (L3524); 인벤토리 L25 |
| 4 | 슬롯 충돌 | 소진 시각을 말한 뒤 가능한 시간을 다시 조회한 `CCARD-TIME`으로 돌려보낸다. 예약 흐름 전체를 처음부터 시작하지 않는다. | `BOOK-RACE-01~07` (L3546–3552); 인벤토리 L103 |

### 버튼과 동작 — 확정 1종

| 버튼 | 동작 | 실행 성격 | 근거 |
|---|---|---|---|
| `[예약 신청하기]` | 현재 확인 데이터로 예약 API를 한 번 호출한다. 성공하면 `CCARD-BOOKDONE`, 충돌이면 갱신된 `CCARD-TIME`, 그 밖의 실패면 같은 카드의 실패 상태가 된다. | 되돌릴 수 없는 실행의 최종 확인 | `BOOK-CONF-04b`, `BOOK-CONF-05~09` (L3516, L3520–3524); `BOOK-RACE-01~07` |

- 값 수정은 앱 규칙상 항목별 `[고치기]` 없이 뒤로가기로 처리한다. 채팅 카드에서 “뒤로”에 해당하는 정확한 대화 동작은 **확인 필요**이며 임의의 수정 버튼을 추가하지 않는다. [근거: `BOOK-CONF-01~04` (L3512–3515); 정본 L88]

### 채팅 그릇 이슈와 정합성

- 여섯 확인 항목을 앞선 봇 문장에 흩어 놓지 않고 신청 직전 카드가 한 묶음으로 재확인해야 한다. 방문이유가 비어 있으면 없는 값을 만들어 채우지 않는다. [근거: `BOOK-CONF-01~02` (L3512–3513); `BOOK-WHY-03` (L3503); 정본 L11]
- 방문이유는 최대 100자의 선택 입력이고 문진 첫 문항의 초기값일 뿐이다. 이후 문진 수정으로 예약의 방문이유를 바꾸지 않는다. [근거: `BOOK-WHY-01~06` (L3501–3506); 정본 L23, L46]
- 예약 중 상담 시트에서는 이 카드를 보내지 않는다. 독립 `AI 상담`에서만 예약 카드 흐름을 사용한다. [근거: `BOOK-BOT-07` (L3437); 정본 L14, L50]

## 3. 예약완료 카드 `CCARD-BOOKDONE`

### 목적과 재현 규칙

- 예약 API의 실제 성공 상태를 신청/확정으로 구분해 번호와 다음 행동을 제공한다. [근거: 인벤토리 L26, L53; 정본 L49]
- 재현 규칙: `BOOK-DONE-01~07`. [근거: 정본 L49; `screen-behaviors.md` L3526–3538]

### 상태 변형 — 4종

| # | 상태 | 카드 계약 | 근거 |
|---:|---|---|---|

| `[내용 보기]` | 작성완료·진료 시작 전, 진료중 이후·과거 답 보존 | 기존 문항과 답을 전용 문진 화면에서 연다. 작성완료·진료 시작 전에는 `[수정하기]`와 함께, `진료중`부터는 이 버튼만 표시한다. | `CARD-QNR-02~05` (L3231–3234); `APPT-QNR-03~06` (L3676–3679); 결정회의 안건 5 L214–216; 결정로그 R2-5 |
| `[작성한 문진 보기]` | 예약 취소·작성 답 있음 | 취소 예약에 보존된 문항과 답을 읽기 전용으로 연다. | `QNR-LIVE-01~05` (L3984–3988); `APPT-QNR-06` (L3679); `CCARD-CANCELDONE-QNR-01`; 결정회의 안건 5 L219–222; 결정로그 R2-5 |
| `[새로 예약하기]` | 예약 취소 | 새 예약 흐름을 열고 취소 예약의 문진을 자동 복사하지 않는다. | `CANCEL-DONE-03·08` (L3789, L3794); `CCARD-CANCELDONE-NEW-01`; 결정회의 안건 5 L219–222; 결정로그 R2-5 |

### 채팅 그릇 이슈와 정합성

- 문항이 최대 30개일 수 있으므로 카드에는 상태·진행률·진입 행동만 담고 문진 문항을 긴 대화문으로 나열하지 않는다. 문진 입력 화면 자체의 그릇은 기존 마법사 규칙을 따른다. [근거: 인벤토리 L30; `QNR-FORM-01~03·08` (L4025–4027, L4033)]
- 진행률은 지나간 문항 수/진료받는 사람에게 보이는 문항 수이며, 빈 답도 지나간 문항으로 센다. 로그인 사용자의 성별로 다시 계산하지 않는다. [근거: `QNR-PROG-01~05` (L3899–3903); `QNR-SHOW-01~05` (L3966–3970)]
- `required`는 환자를 막는 조건이 아니라 병원이 꼭 확인해야 할 표시다. 카드나 문진 흐름이 빈 필수 답 때문에 다음/제출을 막지 않는다. [근거: `QNR-REQ-01~05` (L4007–4011)]
- 완료는 마지막 확인의 `[제출하기]` 때만 기록한다. 현재 구현에는 올바른 완료 판정 칸이 없으므로 구현 계약이 마련되기 전에는 행 존재만으로 완료를 표시하면 안 된다. [근거: `QNR-STATE-04·07~08` (L3889, L3892–3893); 정본 L97]
- 문항 ID·당시 질문 글자 저장, 30문항 상한, 0문항 서버 검증은 아직 구현 전제다. 카드가 이를 구현 완료로 가정하면 안 된다. [근거: `QNR-ID-10` (L3925); `QNR-FORM-09` (L4034); 정본 L98]

## 8. 빠른답변 버튼 묶음 `CCARD-QUICK`

### 목적과 재현 규칙

- 환자가 무엇을 물을 수 있는지 발견하고 타이핑 부담을 줄이되, 누른 문장을 자연스러운 환자 메시지로 전송한다. [근거: 인벤토리 L31, L58; 결정로그 L804–818]
- 재현 규칙: 결정로그 L816–825(시작 묶음과 메시지 저장), L827–833(대화 중 생성·안전·개수·자유 입력). [근거: 정본 L13, L25, L65–66]

### 상태 변형 — 5종

| # | 상태 | 카드 계약 | 근거 |
|---:|---|---|---|
| 1 | 시작·다가오는 예약 있음 | 앱이 고정 4개 `내 예약 확인해줘`, `예약을 바꾸고 싶어요`, `진료 전에 준비할 게 있나요`, `주차할 수 있나요`를 고른다. | 결정로그 L820–825 |
| 2 | 시작·다가오는 예약 없음 | 앱이 고정 4개 `진료시간이 어떻게 되나요`, `어느 과에 가야 할지 모르겠어요`, `예약하려면 어떻게 하나요`, `주차할 수 있나요`를 고른다. | 결정로그 L820–825 |
| 3 | 대화 중 | AI가 바로 앞 질문에 맞는 답 3~4개를 생성한다. 진단·처방을 유도하는 문구는 금지한다. | 결정로그 L827–833 |
| 4 | 생성 중 | 시작 묶음에는 생성 중이 없다. 대화 중 생성 대기에도 스켈레톤·준비 중 문구 등 별도 표시를 하지 않고 자유 입력을 계속 열어 둔다. 성공한 경우에만 추천 3~4개를 표시한다. | 인벤토리 L31·L126; `CCARD-QUICK-LOAD-01`; 결정회의 안건 2 L67–80; 결정로그 R2-2 |
| 5 | 생성 실패 | 실패 안내·재시도 버튼을 표시하지 않고 자유 입력을 계속 열어 둔다. 추천 실패를 상담 전체 오류로 확대하지 않는다. | 인벤토리 L31·L58·L126; `CCARD-QUICK-ERR-01`; 결정회의 안건 2 L67–80; 결정로그 R2-2 |

### 버튼과 동작 — 동작 1종, 표시 개수는 고정 4개 또는 동적 3~4개

| 버튼 | 동작 | 근거 |
|---|---|---|
| `[추천 문장]` | 버튼에 보인 문장을 그대로 환자가 보낸 말풍선으로 저장·전송하고, 그 메시지에 대한 일반 대화 처리를 시작한다. 별도 선택 코드로 저장하지 않는다. | 결정로그 L816–818; 정본 L13 |

### 채팅 그릇 이슈와 정합성

- 빠른답변은 실행 카드가 아니라 대화를 돕는 버튼 묶음이다. 자유 입력을 덮거나 다음 입력을 버튼으로 제한하지 않는다. [근거: 결정로그 L811–818, L833]
- 시작 묶음을 AI가 생성하지 않는다. 앱이 다가오는 예약 유무만으로 고정 묶음을 선택해 매번 같은 상황에 같은 버튼을 제공한다. [근거: 결정로그 L820–825]
- 대화 중 버튼에도 진단·처방 금지 규칙을 동일하게 적용한다. 환자가 스스로 진단명을 말한 것처럼 보이는 버튼을 만들지 않는다. [근거: 결정로그 L827–833]
- 대화 중 추천은 생성 성공 때만 표시한다. 생성 중·실패 상태는 추천 묶음 자리에 아무 표식도 추가하지 않으며 자유 입력 상태를 바꾸지 않는다. [근거: `CCARD-QUICK-LOAD-01`·`CCARD-QUICK-ERR-01`; 결정회의 안건 2 L67–80; 결정로그 R2-2]
- `quick_replies` 메시지 타입과 앱·웹 구현 계약은 아직 반영 전이므로 구현 완료로 단정하지 않는다. [근거: 정본 L93]
