## 이 색인 자체의 충돌·미결 판정

> 범위: 이 파일(`SPECINDEX-patient-app.md`)만 판정한다. 다른 영역 색인과 감사 보고서는 이 판정에 포함하지 않는다.

- **현재 정본끼리의 직접 충돌은 없음.** 아래 폐기·교체 항목은 옛 스펙·플랜과 현재 결정을 구분해 기록한 역사적 충돌이다.
- **미결·미반영은 남아 있음.** 설계 결정은 기록됐지만 스펙·플랜·migration·신규 화면에 아직 옮기지 않은 항목을 뜻한다.
- **대상 미확인은 색인 오류가 아님.** 아직 생성되지 않은 신규 migration·화면·타 담당 영역의 파일·줄을 placeholder로 표시한 것이다.

### 남은 미결·미반영

- 다음 migration 파일은 아직 없고, 실행 기준만 `00010_*.sql`로 확정되어 있다. 옛 플랜의 `00200~00204`는 재작성 때 폐기·재번호한다. (머리말의 migration 기준)
- 알림 설정·알림함·읽음 API/화면의 신규 target이 없다. (기능 갭 `#5/#22/#81`, 기능 갭 대상 파일 보강, 구조 결정의 알림 선호도)
- `support_requested_at + request_type`, 예약-티켓 FK, 3-A 상담 연동, 직원 `/today`·캘린더 연결의 실제 파일·줄이 없다. (기능 갭 `#6`, 구조 결정의 공통 마감 후 지원 요청·알림 원장·상담봇 앱 연동)
- 부분 문진 저장·문진 RLS·의사 화면·관리자 문진 화면 일부 target이 `대상 미확인`이다. (기능 갭 `#17/#50~#57/#77`, 구조 결정의 문진·RLS 계약, 후반 결정 `AD-050`)
- 예약 요청 UUID 멱등성, 가입 동의, 알림 템플릿 설정표·migration의 실제 target이 없다. (구조 결정의 예약 생성 요청 ID·가입 동의·알림 템플릿 계약, 기존 체크박스 미반영분)
- 상담봇 상담방·이전 상담·인증 복귀 카드 화면은 코4 담당 신규 산출물이라 이 색인에서는 `대상 미확인`이다. (상담봇 연동, `MR2-02`, `MR2-03`)
- 기존 결정로그 체크박스 묶음은 결정 부재가 아니라 스펙·플랜 재작성 전의 `미반영` 상태다. (섹션 `4. 기존 체크박스 미반영분`)

### 재작성 순서

1. **색인 입력 고정**: 이 색인과 `screen-behaviors` 묶음 0~8을 환자 앱 재작성 입력으로 지정한다. 플랜에 `test('[규칙ID] ...')` 문장을 직접 포함한다.
2. **스펙 정리**: `patient-app-design.md`의 폐기 문장을 먼저 교체한다. 특히 변경 마감 후 상담, 진료 시작 전 문진 수정, 설정 하위 화면, 알림함, 로컬 캐시, 자동확정 기본값을 한 번에 갱신한다.
3. **공용 migration/API 계약**: 실제 다음 파일을 `supabase/migrations/00010_*.sql`부터 시작하고, 논리적으로 나누면 `00011+`로 순차 증가시킨다. support 요청·문진 완료/ID·notification preferences/log·SMS 실패·알림 종류 설정·환자 확인 시각·멱등 키를 묶고 RLS/부분 unique/상태 전이를 명시한다. 옛 `00204_notification_log.sql` 표기는 재작성 때 폐기하고, 상담봇 3-A의 `notification_log`·예약-티켓 FK가 충돌하지 않는지 확인한다.
4. **환자 플랜 재작성**: Task 1~26을 현재 계약으로 다시 배열하고, 신규 설정/알림함·로컬 캐시·부분 문진 저장·예약 멱등성·OTP 서버 제한·비밀번호 정책·병원 정보 화면 태스크를 추가한다. 기존 태스크를 줄번호 패치하지 않는다.
5. **상담봇·직원 웹 교차 검토**: MR2-02~04, 역대조-1·6, AD-050·051·067·068, 3-A를 코4/코2/코3 색인과 대조한다. 담당 영역 밖의 화면은 여기서 구현하지 않고 계약·영향만 확인한다.
6. **기계 검증**: 규칙 ID 유령 0, 색인에 적은 규칙 ID 전부 실재, 모든 기능 갭의 대상 파일/줄 존재, 존재하지 않는 태스크·가짜 규칙 ID가 영향 대상에 남지 않았는지, 줄번호 placeholder가 없는지, 폐기 대상 문구의 잔재 0을 확인한다.
