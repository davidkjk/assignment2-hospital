④ 5회 틀려 잠긴 뒤 — 병원 안내

이름 맞히기를 반복하게 두지 않습니다(AUTH-PWNEW-15). 5회를 넘기면 그 번호의 재설정을 잠그고 병원 안내로 보냅니다.
⭐ 이 화면이 갭 #44의 「탐지」입니다(AUTH-PWNEW-13) — 번호를 물려받은 사람은 이름을 몰라 반드시 여기로 옵니다. 지금 설계에서는 아무도 모르게 계정이 넘어갑니다.
📌 문구는 AUTH-TEL-*(번호가 바뀐 경우)와 같은 화면을 씁니다 — 진짜 환자와 번호를 물려받은 사람이 같은 곳에서 막히므로 둘 다 병원으로 안내합니다(AUTH-PWFIND-06과 같은 처리).

· ⭐ 대조는 서버가 합니다(AUTH-PWNEW-09). ⚠️ 저장된 이름을 앱으로 내려보내면 안 됩니다 — 내려보내면 번호를 물려받은 사람이 화면(또는 통신 내용)에서 앞 사람 이름을 읽고 그대로 입력합니다. 목록 마스킹에서 원본을 안 내려보낸다고 정한 것(MASK-SRV-01)과 완전히 같은 처리입니다.
· 공백은 지우고 비교합니다(AUTH-PWNEW-10) — 홍 길동과 홍길동을 다르다고 하지 않습니다. 고령 사용자가 띄어쓰기로 막히는 것은 얻는 것 없는 손해입니다.
· 생년월일까지 묻지 않습니다(AUTH-PWNEW-16) — 칸이 늘수록 진짜 환자가 막히고, 생년월일은 이름보다 더 쉽게 알려집니다.
· 이 화면은 문자 인증을 통과한 사람만 도달합니다. 그래서 등록된 이름과 다릅니다가 가입 여부를 새로 흘리지 않습니다(AUTH-PWFIND-03·05와 충돌하지 않음).
⚠️ 이 칸이 막는 것과 못 막는 것 — 「이제 안전하다」로 읽으면 안 됩니다
· ✅ 막는 것 — 번호 재활용(갭 #44): 통신사가 번호를 다른 사람에게 넘겼을 때, 새 주인은 앞 사람 이름을 모르므로 여기서 멈춥니다.
· ❌ 못 막는 것 — 가족·지인(AUTH-PWNEW-14): 가족은 이름을 압니다. 갭 #10이 "이름·생년월일은 가족·지인이 다 안다"고 한 그대로입니다. 이 앱은 가족 연결 기능이 있어 가족 간 무단 접근이 실제 시나리오입니다.
· 📌 그래도 후퇴는 아닙니다 — 지금은 둘 다 못 막습니다. 다만 절반을 막았다고 전부를 막은 것으로 착각하지 않기 위해 이 한계를 규칙에 못박아 뒀습니다.
· ⭐ 갭 #10과 충돌하지 않습니다: #10이 기각한 것은 이름 단독으로 계정을 넘기는 경우(전화로 번호 변경 요청)였습니다. 이번은 문자 인증 위에 얹는 것이라 침입자가 폰도 쥐고 있어야 하고 이름도 알아야 합니다.
· ⏳ 완전히 풀려면 「휴대폰 본인확인」(PASS)이 필요합니다 — 통신사 명의의 이름을 검증해 돌려주므로 가족이라도 남의 명의로는 통과하지 못합니다. 대가는 본인확인기관 계약·건당 비용이고, 요구사항 4.1은 명의 검증을 요구하지 않았습니다(고객요구사항.txt:235) → 미결 C-5(사용자 결정 대기).
