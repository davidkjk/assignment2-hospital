그리고 그 값이 사전문진의 「보일 대상」을 가릅니다(QNR-SHOW-01) — 요구사항 4.4가 지정한 다섯째 문항이 임신 가능성이라, 아들에게 임신 문항이 뜹니다.

🔄 2026-08-05 정정 — 「비밀번호 확인」 칸이 빠져 있었다(사용자 지적)
처음 그린 그림에는 확인 칸이 없었고, 동작 명세 AUTH-PROFILE-03도 가입 화면에는 확인 칸을 두지 않는다라고 적혀 있었습니다. 둘 다 틀렸습니다.
2026-08-01에 사용자가 직접 「두 번 치게」로 확정했고(결정 문서 :407), 적용 범위도 가입·비밀번호 찾기·비밀번호 변경 세 화면이라고 명시돼 있었습니다(:410).
· 확정 근거: 비밀번호 설정은 틀렸을 때 대가가 큰 화면입니다 — 잘못 정하면 다음 로그인부터 못 들어가고, 되돌리려면 SMS 인증을 다시 거쳐야 합니다. 이 앱은 전화번호가 바뀐 환자가 계정에 영영 못 들어가는 문제가 이미 있습니다(갭 #19).
· ⛔ 기각된 안(확인 칸 없애기)의 허점: 타이핑은 절반이 되지만 그 안전은 「사용자가 눈 버튼을 누른다」는 전제 위에 있습니다. 안 누르고 넘긴 사람에게는 장치가 하나도 안 남습니다. 확인 칸은 눈을 안 눌러도 두 번 친 것이 다르면 잡아냅니다.
⚠️ 규칙 쪽 근거 칸에 확신 낮음 표시가 붙어 있었습니다 — 확신이 낮았던 게 아니라 이미 확정된 결정을 못 찾은 것이었습니다. → AUTH-PROFILE-03b~03e로 되돌림.
그림에 안 보이지만 이 화면에 걸린 규칙
· 이 화면에 도착한 사람은 이미 로그인 상태입니다(AUTH-SIGNUP-07). 인증번호가 맞은 순간 서버가 출입증(세션)을 발급하므로, 계정은 이미 존재하고 이름·생년월일만 비어 있습니다.
· 그래서 여기서 앱을 꺼도 ③으로 돌아옵니다(AUTH-SIGNUP-08, B-6). 문자 인증을 다시 시키지 않습니다 — 앱을 껐다 켜는 가장 흔한 이유가 문자가 안 와서인데, 그 사람에게 문자부터 다시 받으라고 하면 같은 자리를 맴돕니다.
· ⚠️ 구현에 「가입 미완료」 상태가 없습니다(AUTH-SIGNUP-11) — 플랜의 로그인 상태는 signedOut/signedIn 둘뿐이라 이 되돌리기를 만들 자리가 없습니다. 판정 기준은 「출입증은 있는데 프로필이 없으면 가입 미완료」(AUTH-SIGNUP-12).
· 비밀번호 조건이 서버와 어긋납니다(AUTH-PROFILE-02) — 서버는 minimum_password_length = 6에 문자 종류 조건이 없습니다(config.toml:182·185). 서버를 화면에 맞춥니다(갭 #25).
· 가입 성공 → 곧장 홈입니다(AUTH-PROFILE-07). 축하 화면을 따로 두지 않습니다.
· 가입 실패 → 버튼 위 붙박이 오류(AUTH-PROFILE-08). ⭐ ①②를 다시 하게 만들지 않습니다 — 인증은 이미 끝났고, 다시 시키면 본인 잘못이 아닌 일로 처음부터가 됩니다.
