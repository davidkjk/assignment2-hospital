C. 전용 안내 화면, 전화 우선

팝업이 아니라 화면 하나를 쓰고, 전화를 첫 번째 버튼으로 올립니다. 마감 후 취소는 급한 상황일 때가 많다는 판단. 단점: 병원 전화 응대 부담이 커지고, 문의가 기록에 남지 않습니다(티켓 없음).

추천

A(제안하신 안)를 추천합니다. 팝업이 "왜 안 되는지"를 먼저 말해주므로 환자가 앱을 탓하지 않고, 전화번호가 함께 있어 급한 사람은 즉시 해결합니다. 무엇보다 [닫기]로 빠져나갈 수 있다는 게 중요합니다 — B는 취소를 망설이던 사람도 일단 상담방에 들어가게 만들어 불필요한 티켓을 늘립니다(직원 업무량 증가).

A를 고르시면 [상담 연결하기] 이후 화면은 B의 상담 화면을 그대로 씁니다 — 봇 첫 메시지 + 확인 카드. 이때 카드 버튼은 "네, 상담으로 연결해 주세요"이고, 이 버튼을 눌러야 비로소 직원 웹의 취소요청 대기열에 나타납니다.

C는 전화를 우선하는 게 환자에겐 빠르지만, 상담 기록(`support_tickets`)이 남지 않아 스펙 3.9·3.10의 상담 통계·지식 개선 사이클에서 빠집니다. 전화는 보조 수단으로만 두는 게 맞습니다.

확인 필요 화면에 "24시간"이라고 적었지만, 실제 마감 기준은 병원이 의사별 스케줄에서 설정하는 값입니다(스펙 3.7 "예약마감"). 그래서 문구는 설정값을 읽어 "진료 시작 24시간 전"처럼 자동으로 채워지게 만들어야 합니다. 고정 문구로 박아두면 병원이 설정을 바꿨을 때 화면이 거짓말을 하게 됩니다.
