2026-08-06 기준 · 「어디서 시작해 어디로 들어가 무엇을 하나」를 업무 순서로 정리. 근거는 screen-behaviors.md의 NAV-* 규칙 36개.

⭐ 정리가 되냐고 물으셨는데 — 됩니다. 화면은 안 그렸어도 어디에 무엇이 있는지는 이미 정해져 있습니다. ⚠️ 다만 흐름이 「끊긴 곳」이 세 군데 보입니다 — 맨 아래 「빈틈」 절에 모았습니다.

3. 업무별 흐름 — 어디서 들어가 무엇을 하나

⭐ 대부분의 일이 문을 두세 개 가집니다. 창구에서 손에 무엇이 먼저 잡히느냐가 매번 다르기 때문입니다 — 전화가 먼저 오기도, 환자가 먼저 서 있기도 합니다.

① 전화 예약을 잡는다 규칙 확정

캘린더 빈 곳 클릭→ 오른쪽 패널→ 환자 찾기(왼쪽 표)→ 등록
검색에서 [예약 잡기]→ 캘린더로 이동 + 패널→ 캘린더에서 시간 찍기→ 등록 → 검색 결과로 복귀

⭐ 시간부터냐 사람부터냐만 다르고 같은 패널에서 만난다. 끝나면 출발한 화면으로 돌아온다.

② 예약 없이 온 환자를 줄 세운다(당일 방문) 규칙 확정

/queue [＋ 당일 방문 등록]→ 오른쪽 패널→ 환자 찾기 · 의사 · 오신 시각→ 「진료 대기」 맨 뒤
검색에서 [당일 방문 등록]→ 같은 패널(환자 채워짐)→ 등록

⭐ 못 찾으면 그 자리에서 신규 등록으로 이어진다 — 화면을 옮기지 않는다. ⭐ 「아까 오셨어요」·「어제 오셨어요」도 같은 패널에서 받는다.

③ 도착한 환자를 접수한다 규칙 확정

/today 「접수 안 됨」 카드→ [도착 처리]→ 그 자리에서 처리 · 되돌리기 가능
환자가 QR·예약번호를 내밀면→ /checkin (미설계)→ 도착
이름으로 찾아서→ 검색 결과 줄의 [도착 처리]→ 도착

⭐ 확인창이 없다. 대신 되돌릴 수 있게 했다 — 확인창은 매번 손을 멈추지만 실수는 가끔이다.

④ 예약을 바꾸거나 취소한다 규칙 확정

캘린더에서 예약 블록 클릭→ 오른쪽 상세 패널→ [시간 변경] / [예약 취소]→ 사유 적고 확인
/today·/queue의 [재예약]→ 캘린더 + 그 예약 패널이 열린 채

⭐ /today·/queue에는 예약 상세가 없다 — 전부 캘린더 패널로 보낸다. 고치는 곳은 한 군데다.

⑤ 대기 순서를 바꾼다 규칙 확정

/today 「오래 대기」 [대기 목록에서 보기]→ /queue 그 줄이 강조된 채→ 끌어서 옮김→ 사유 팝업 → 확인

⭐ 사유를 적기 전에는 순서가 바뀌지 않는다. 바깥을 눌러도 창이 안 닫힌다.

⑥ 환자를 찾아 살펴본다 상세 화면 미설계

/patients 한 칸 검색→ 결과 줄 클릭→ /patients/:id (미설계)

⭐ 모든 목록 화면이 같은 곳으로 간다 — 돌아오면 검색어·필터·스크롤 위치가 그대로다. 이름·전화·생년월일 어느 조각으로도 찾는다.

⑦ 의사가 진료한다 화면 미설계

로그인(의사)→ /doctor/console→ 환자를 여는 순간→ 「진료중」 자동 전환

⚠️ [진료 시작] 버튼이 없다 — 여는 순간이 곧 시작이라 시각이 정확해진다. ⚠️ 대신 잘못 열면 되돌릴 수 없다(갭 #82).

⑧ 관리자가 일정을 바꾼다 해소 2026-08-07 · 목업 66

/admin/schedule 휴진 등록→ 저장 전 경고 + 안내 대상 고르기→ /today 「확인 필요한 예약」 행→ 직원이 옮기기 / 취소 / 그대로 두기→ 캘린더에 ⚠ 확인 필요

✅ 가운데 두 칸이 채워졌다(SB-32 · SCHED-* 23개 · TODAY-RESCHED-04~11). ⭐ 새 화면을 만들지 않았다 — 관리자 팝업은 플랜에 이미 있었고(AffectedAppointmentsDialog), 직원 진입점도 규칙에 이미 있었다(TODAY-RESCHED-01~03). 없던 것은 행에서 할 수 있는 일뿐이었다.

4. ⚠️ 흐름이 끊긴 곳 — 여기가 다음 할 일

⭐ 좋은 소식 — 셋 다 「그림만 없는 것」이었다(2026-08-06 원문 대조). 서버·DB는 이미 다 있다. 새로 만들 기능이 아니라 그리기만 하면 되는 것들이다.
📌 다만 「끊겼다」의 뜻이 셋 다 다르다 — ①은 갈 곳이 없다, ②는 말할 문장이 없다, ③은 그릴 화면이 없다.
#끊긴 곳무엇이 없나
1 일정 변경 → 환자 안내
해소 2026-08-07		 ✅ 이어졌다(SB-32 · 목업 66 · SCHED-CALC-*·SCHED-DONE-*·SCHED-WARN-* · TODAY-RESCHED-04~11).
⭐⭐ 「화면이 없다」가 절반 틀렸다 — 관리자 팝업은 플랜에 이미 있었고(AffectedAppointmentsDialog Task 12/18), 직원 진입점도 규칙에 이미 있었다(TODAY-RESCHED-01~03). 새 화면을 만들지 않았다.
⭐ 먼저 「미결정 #1」(2026-08-02부터 대기)을 풀어야 했다 — 명단을 계산으로 만드나 도장으로 만드나. → 계산이 명단을 만들고, 도장은 「사람이 처리했나」만 담는다.
🆕 대조 중 갭 #88·#89·#90이 나왔다 — 특히 #89는 플랜의 「안내 대상」 체크가 실제로는 전부 병원취소이고 기본이 전체 선택이다.
2 두 직원이 같은 자리를
해소 2026-08-07		 ✅ 이어졌다(SB-42 · 목업 65 ⑥절 · CAL-RACE-01~08 · CAL-LIVE-01~04).
⭐⭐ 물어보니 「저장할 때 갈리는 문제」가 아니라 「저장 전에 막을 수 있는 문제」였다 — 내 자리표가 있는 자리에 다른 예약이 들어오면 그 즉시 ⚠ 방금 찼습니다로 바뀐다(CAL-RACE-02).
⚠️ 그러려면 캘린더가 실시간이어야 하는데 CAL-LIVE-*가 0개였다 — /today·/queue엔 있고 캘린더에만 없었다.
✅ 그래도 409를 만나면 패널은 그대로 두고 시간 칸만 비운다 — 자리만 뺏겼지 환자·의사·사유는 유효하다(TODAY-RACE와 다른 점).
3 화면 규칙이 0개인 것 셋 ✅ DB·서버 다 있다 — 내부 메모(patient_internal_notes 조회 코드) · 직원 계정(/admin/staff 라우트).
⬜ 없는 것은 그림. /patients/:id · /admin/staff · 챗봇.
⚠️⚠️ 모든 흐름의 밑바닥에 갭 #85가 있다 — 예약에 실제 시각 칸이 없어 5분 단위 예약·당일 방문·사이 끼워넣기가 전부 걸립니다. 2026-08-06에 「나중에」에서 「선행 조건」으로 격상됐습니다.
