## 범주 6 — 시각(겉모습)을 실 구현에 연결 (사용자 지적 2026-08-24 — 자동으로 안 따라감)

> DESIGN-NOTES.md·데모 컴포넌트는 규칙이 아니라 "시각 레퍼런스"라 TDD 테스트가 안 지킨다. **플랜/브리프에 화면마다 명시적으로 링크를 박아야** 워커가 본다. 안 박으면 누락.

- [ ] **플랜 각 화면 태스크에 「시각 레퍼런스」 링크 추가** — 각 태스크에 ①데모 컴포넌트 파일 경로 ②`demo/DESIGN-NOTES.md`의 해당 절. (환자앱·직원웹·챗봇 플랜 전부)
  - ⭐ **surface별로 문구가 다르다(스택 확인 2026-08-24)**: **직원 웹·웹 상담창(React+TS)** = "이 데모 컴포넌트를 **기본 틀로 포팅**"(구조·레이아웃 그대로, 가짜데이터→React Query, 하드코딩 토큰→tokens.json). **환자 앱·앱 상담 탭(Flutter)** = "이 데모 화면을 **시각 기준으로 Flutter 재현**"(코드 못 옮김, 보이는 것만 일치). 환자 앱은 어느 길로 가도 데모=시각 명세(웹/RN 전환 비추천).
- [ ] **브리프에 frontend-design 스킬 호출 명시** — ⚠️ frontend-design은 **Superpowers가 아닌 별도 플러그인**이라 자동 호출 안 됨(사용자 확인 2026-08-24). Claude 워커=브리프에 "invoke frontend-design"; Codex 워커=스킬 지침을 브리프에 텍스트로 넣거나 시각 핵심 화면은 Opus로.
- [ ] **(선택) 검사기** — 라우트가 있는 플랜 태스크마다 「시각 레퍼런스:」 줄이 있는지 grep 검사(누락 방지, 「약속은 검사기에」 원칙).
- [ ] **(선택) 규칙 취지 구체화 승격** — 해석이 헷갈렸던 규칙 몇 개만 데모 구체화를 규칙에 한 줄로(예: `QUEUE-ORDER-04` 삽입선·`TICKET-DETAIL-CONV-01` 좌우분리). 필수 아님.
