## 1. `[결정]` ⭐ 카드 「계층」이 갈린다 — 가장 크고 여러 화면에 걸침

> ✅ **결정됨(2026-09-02): ㉮ 데모식 되살리기**(보조 컨테이너=테두리, 그림자 제거). 세션9의 「전부 그림자」 결정을 뒤집음. 실행은 `parity-lane3`(설정·가족·인증) + `parity-lane2`(알림함 내부). `_SettingsLink` 헬퍼부터 → 되살린 뒤 profile 에뮬 눈확인.

### 무슨 차이인가
데모는 카드를 **두 등급**으로 나눈다:
- **주요 콘텐츠 카드** = 그림자만(`shadow-(--elevation-card)`, 테두리 없음) — 예: 홈 예약 카드, 알림 상태카드 본체, 병원정보 카드, 예약목록 행.
- **보조 그룹/절차/설정 리스트** = 옅은 테두리만(`rounded-xl border`, 그림자 없음) — 예: 설정 링크 행, 약관 동의 리스트, 전화번호 변경 절차 카드, 탈퇴 화면 섹션들.

Flutter는 세션9 리스킨 때 **양쪽을 전부 그림자 카드로 통일**했다. 그래서 **보조 컨테이너가 데모보다 무겁게(다 떠 보이게)** 보인다.

### 성격 — 이건 「버그」가 아니라 「뒤집을지」의 문제
세션9에 **의도적으로** 테두리→그림자로 바꾼 것이고, 그때 실기기로 확인·승인까지 받았다. 이유는 *"딥틸 톤 배경 위에서 옅은 회색 테두리가 와이어프레임처럼 보인다"*였다. 그런데 **데모도 똑같은 배경(#F2F5F7)** 위에서 보조 컨테이너에 테두리를 그대로 쓴다 — 즉 데모 디자이너는 그 배경에서도 테두리가 괜찮다고 판단한 것.

**추천: 데모의 2단 계층을 되살린다(보조 컨테이너를 테두리로).**
- **장점**: 데모와 진짜로 일치. 화면 위계가 또렷해진다("이건 주요 카드 / 이건 그냥 이동 링크"를 눈이 구분). 설정·탈퇴처럼 리스트가 많은 화면이 덜 무거워진다.
- **단점**: 세션9의 승인된 결정을 뒤집는 것 → 되살린 뒤 **실기기로 다시 눈확인**이 필요(테두리가 배경에 묻히지 않는지). 공용 헬퍼 하나(`_SettingsLink` 류)를 고치면 대부분 반영되지만, 화면마다 손이 조금씩 간다.
- **대안(유지)**: 지금처럼 전부 그림자로 둔다. 데모와는 다르지만 "이미 승인된 화면"을 안 건드림. 위계 구분은 약해진다.

> ⚠️ 이 항목은 규모가 있으니 **여기부터 하나 정하고** 나머지로 넘어가는 걸 권합니다.

## 2. ✅ 의사 실사진 — **실사진으로 결정**(2026-09-02). 시드 `photo_url` 채우면 됨(위젯 준비됨)

### 무슨 차이인가
데모에 **아직 커밋 안 된 최신 변경**이 있다: 의사 **실사진 7장**(`demo/public/doctors/*.jpg`) + `DoctorAvatar`에 `photoUrl` 분기 추가. 이제 데모 의사 선택(3단계)·최종확인(7단계)·예약상세에 **실제 얼굴 사진**이 뜬다.

### Flutter 현황 — 위젯은 이미 준비됨
`widgets/doctor_avatar.dart`는 **이미 `photoUrl`을 지원**한다: 사진이 오면 원형 사진, 없으면 **회색 원 + 이름 첫 글자**. 그리고 이 폴백(회색 원+글자)은 규칙 `BOOK-DOC-05`가 못박은 정답이라 **맞다**.
반면 데모의 무사진 폴백이 이번에 **일러스트 얼굴(색 배경+청진기+안경)**로 바뀐 건 규칙 위반 → **이식 금지**.

### 그래서 결정할 것
**Flutter 앱에서도 실제 의사 사진을 보이게 할까?**
- 지금 상태로는 시연 시 **의사들이 전부 회색 원**으로 보인다(시드 데이터에 `photo_url`이 없어서). 데모는 사진, 실앱은 회색 원 → 나란히 보면 다르다.
- **사진을 보이려면**: 백엔드 시드의 `doctors.photo_url`에 사진 URL을 넣거나(권장 — 코드 0줄, 데이터만), 데모와 같은 7장을 앱 에셋으로 넣고 매핑. **위젯 코드는 손 안 대도 됨.**
- **추천**: 시연 임팩트를 위해 **시드에 photo_url만 채운다**(데모의 7장을 백엔드가 서빙하거나 공개 URL로). 규칙(폴백 회색 원)은 그대로 두고, 데이터만 있으면 사진이 뜬다.

## 4. `[규칙승]` 이식 금지 — 데모가 느슨하고 규칙/구조가 이기는 곳 (확인용)

이미 핸드오프에 정리됐지만, "달라 보인다"고 잘못 옮기지 않도록 재확인:
- **의사 무사진 폴백** = 회색 원+글자(`BOOK-DOC-05`). 데모의 일러스트 얼굴은 **옮기지 않음**.
- **아이콘 채움**(`DISP-ICON-03`) = 이미 전부 채움. 데모가 선 아이콘이어도 채움 유지.
- **최종확인 행 구성·일시 결합·버튼 「예약 신청하기」**(`BOOK-CONF-02/04b`), **문진 진행 「N번 / M문항」**(`QNR-PROG-06`), **예약 단계명 「대상 선택」**(`BOOK-NAV-02`) = 규칙 소유, 데모 문구 안 따름.
- **문진 객관식 옵션**(`QADM-FORM-05`=short/long/yes_no) = 데모가 더 넓음, 이식 금지.
- **OTP 「확인」 버튼**: 데모는 6자리 채우면 자동 진행(버튼 없음), Flutter는 실제 서버 인증이라 명시적 「확인」 버튼 유지 = 구현상 정답, **이식 아님**.
- **회원가입 진행 밴드·랜딩 링크 구성** = 규칙/데모-only(QA 갤러리 등) 섞임. 랜딩의 병원명 `○○의원`은 배포 시 치환되는 자리표시자(데모 `가온병원`을 하드코딩하지 않음).

## 5. 심화 감사(2차, 2026-09-02) — 픽셀·값까지 파고든 결과
