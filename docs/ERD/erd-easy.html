Before you start

선 하나만 읽어도
절반은 이해한 셈입니다.

테이블은 같은 종류의 정보를 모아 둔 ‘장부 한 권’입니다. 연결선은 한 장부의 고유번호를 다른 장부가 빌려 쓰는 관계를 뜻합니다.

PK

기본키 · 대표 고유번호

장부 안에서 한 줄을 확실하게 찾는 번호입니다. 주민번호보다는 ‘시스템 내부 관리번호’에 가깝습니다.

FK

외래키 · 다른 장부 연결번호

다른 테이블의 PK를 가리킵니다. 예: 예약의 doctor_id는 직원 장부의 의사를 찾습니다.

1 : N

하나와 여러 개의 관계

환자 한 명은 예약을 여러 건 가질 수 있지만, 예약 한 건의 실제 환자는 한 명입니다.

NULL

값이 없거나 해당 없음

전화로 등록된 환자는 앱 로그인 계정이 아직 없으므로 auth_user_id가 비어 있을 수 있습니다.

Three distinctions

가장 많이 헷갈리는
세 가지 구분

01

로그인 계정 ≠ 환자

auth.users는 로그인 수단이고 patients는 병원의 환자정보입니다. 전화 접수 환자는 병원 장부에는 있어도 앱 계정은 없을 수 있습니다.

02

예약 시간 ≠ 실제 예약

appointment_slots는 “10시가 비어 있음”이라는 시간표이고, appointments는 “홍길동이 10시를 예약함”이라는 업무 기록입니다.

03

현재 값 ≠ 변경 이력

appointments에는 현재 상태를, appointment_status_history에는 누가 언제 어떤 상태로 바꿨는지를 차곡차곡 남깁니다.

Real workflows

실제 업무 한 건은
이렇게 이동합니다.

화살표는 저장 순서나 조회 방향을 단순화해 보여줍니다. 모든 화살표가 데이터베이스의 FK라는 뜻은 아닙니다.

Mini glossary

용어 사전

UUID
추측하기 어려운 긴 형태의 시스템 고유번호입니다. 대부분의 id에 사용합니다.
UNIQUE
같은 값이 두 번 저장되지 못하게 막는 중복 방지 규칙입니다.
RLS
Row Level Security(행 단위 보안). 같은 장부에서도 로그인한 사람에 따라 볼 수 있는 줄을 제한합니다.
JSONB
질문 목록처럼 모양이 자주 달라지는 묶음 데이터를 PostgreSQL에 저장하는 형식입니다.
Audit log
누가 언제 민감한 정보를 열거나 변경했는지 남기는 감사 기록입니다.
Soft delete
행을 실제로 지우지 않고 is_active=false로 표시해 과거 기록을 보존하는 방식입니다.
